MODULE 02

Auth Module — WhatsApp OTP + JWT

Phase 0 · Build Week 1 · One auth for all clients

Flow

User enters phone → POST /api/v1/auth/send-otp Backend → WA Cloud API sends 6-digit OTP (template: "otp_verification") User enters OTP → POST /api/v1/auth/verify-otp Backend validates → creates/updates users row → issues JWT JWT payload: { sub: userId, role: "customer"|"admin", phone, iat, exp: 7d } Web storage : httpOnly cookie (never accessible from JS) Flutter storage: flutter_secure_storage (never SharedPreferences for JWT)

API Endpoints

EndpointAuthPurpose
POST /api/v1/auth/send-otpPublicSends OTP to phone via WA Cloud API
POST /api/v1/auth/verify-otpPublicValidates OTP → issues JWT + creates user row
POST /api/v1/auth/refreshJWT (near-expired)Silent token refresh
POST /api/v1/auth/logoutJWTInvalidates session / clears cookie
GET /api/v1/auth/meJWTReturns current user profile
✓
One Auth For All ClientsSame JWT works for web (cookie), Flutter (Bearer header), admin panel. No separate auth system. lib/auth/neon-auth.ts is the single source of truth. Admin check: role === "admin" in middleware.

Lead Scoring Prompt Logic

MODULE 10

Orders + Payments Module

Phase 1 · Razorpay · Webhook HMAC verified · Paise always

Payment Flow

User confirms order → POST /api/v1/orders (creates order row, status: pending) → POST /api/v1/payments/create (creates Razorpay order, returns razorpay_order_id) → Frontend loads Razorpay checkout Web: Razorpay.js · Flutter: razorpay_flutter SDK → Payment success → Razorpay fires webhook → POST /api/v1/payments/webhook → Backend: verify HMAC-SHA256 signature FIRST → Update payment status → update order status: confirmed → WA template "order_confirmation" sent to customer → Admin notified via WA

API Endpoints

EndpointAuthPurpose
POST /api/v1/ordersJWTCreate order from cart
GET /api/v1/ordersJWT (admin: all · user: own)List orders
GET /api/v1/orders/:idJWT (owner or admin)Order detail
POST /api/v1/payments/createJWTCreates Razorpay order
POST /api/v1/payments/webhookHMAC signature (no JWT)Razorpay confirms payment
POST /api/v1/orders/:id/cancelAdmin JWTCancel order + trigger refund
⚠
Webhook Security: Verify Razorpay HMAC-SHA256 signature before updating any order. Never trust the payload without verification. Handle retries idempotently using razorpay_payment_id as the dedup key.

RULES

The NEVER List

Violations that cause full rewrites at year 2
  • Never build a second backend for Flutter. Flutter is a client of the Next.js API. One backend. Forever.
  • Never put the admin panel in Flutter. Admin stays web-only at /admin. Phones are not for data management.
  • Never store API keys or secrets in the Flutter app. Every key reachable from mobile is compromised within days.
  • Never use float for money. All monetary values are integer paise. price_paise INT NOT NULL. No exceptions.
  • Never send WhatsApp messages without explicit opt-in. Meta bans numbers. opted_in_whatsapp = true is the gate — every send checks this.
  • Never skip API versioning. All routes: /api/v1/.... Flutter apps can't force-update overnight — old app versions will keep calling the same URLs.
  • Never build Module 15 (AI Interior Render) before Flutter Phase 3. Needs 200+ engaged app users. Without users it burns ₹40–₹100/session with zero conversion lift.
  • Never build HTML-coupled API routes. Every API route returns JSON. Every input is JSON. No server-rendered API responses.
  • Never let admin panel bypass the service layer. Admin actions go through the same service functions the app uses. No direct Drizzle queries in admin route handlers — everything through the service layer.
  • Never tightly couple a feature to one vendor's UI. Pricing changes. Always abstract vendor integrations behind a wrapper function (e.g. lib/whatsapp/client.ts, cached()).
